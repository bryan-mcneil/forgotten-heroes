# Phase 4 — Studio: Corgi Space Cadet (Steps 57–60) `[opt]`

**Where you are:** the game is playable against `dev`. **At the end of this phase:** the game opens
with a short studio intro, the studio has a landing page on your Hostinger hosting, and the app has
proper icons/metadata. All four steps are optional for "a complete game" but they are what makes
it feel *shipped* (think ConcernedApe's logo before Stardew Valley).

> **Deferred (Q14):** the corgi art arrives later, so this phase waits for it. Do it after Step 56 if the
> art is ready, otherwise **after launch** (Step 77) as release 1.1. Step 60 (icons/metadata) needs no
> corgi art and is worth doing before launch anyway.

`knowledge/asset_inventory_and_pipeline.md` §6 (art you supply).

## Step 57 — `[opt]` Brand kit and placeholders
**Branch:** `step-57-brand-kit` · **est 2h**

**Goal:** everything the intro and site need, with placeholders where your art is not ready.

**You will have:** `studio/brand.md` (name, tagline, colours — deep space navy `#0b1026`,
corgi orange `#e39a4c`, star white; type: Pixelify Sans; logo lockup rules; do/don't), placeholder
corgi frames (96×96, 4-frame bob, drawn as simple pixel shapes by a tiny Pillow script
`tools/assets/placeholder_corgi.py` so it is clearly a placeholder), `studio/logo/` (SVG
wordmark "CORGI SPACE CADET" using the pixel font outlines), the star/sparkle sprite.

**Sensei notes:** a brand kit is a contract with your future self: when the real art arrives, only
files change, not code.

**Verify:** placeholder frames render in `/dev/gallery` under "studio".

**Commit:** `step-57: corgi space cadet brand kit and placeholders`

## Step 58 — `[opt]` Intro animation
**Branch:** `step-58-intro` · **est 3h**

**Goal:** the five-second beat sheet, skippable, once per session.

**You will have:** `src/intro/Intro.tsx` (Motion sequence: stars twinkle → corgi floats in with
bob (Sprite) → "boop" + WOOF bubble → wordmark types in → "presents" → fade), `useIntroOnce()`
(`sessionStorage` flag; settings toggle "Show intro"), skip on any key/click/tap, sounds
(`space_hum` loop, `jetpack`, `boop`, `type`), reduced-motion variant (static logo card for 1.5 s),
swap-in guide in `studio/brand.md` for the real corgi frames.

**Sensei notes:** choreograph with a timeline array (`[{at: 0, do: stars}, {at: 500, do: corgi}…]`)
instead of nested timeouts — same idea as the battle playback engine.

**Verify:** intro plays once per session; Esc skips instantly; audio respects mute; Lighthouse unaffected (intro assets lazy-loaded).

**Commit:** `step-58: studio intro animation`

**Check your understanding:** Why is an intro that cannot be skipped considered a UX failure?

## Step 59 — `[opt]` Studio landing page on Hostinger
**Branch:** `step-59-studio-site` · **est 3h**

**Goal:** a home for the studio, deployed from GitHub to the hosting you already pay for.

**You will have:** `studio/site/` — a static page (plain HTML + the same Tailwind build via a
tiny Vite project, or hand-written CSS): hero section with the corgi, "Forgotten Heroes — Play now"
button (CloudFront URL, later the custom domain), 3 screenshots/GIF, "Built with" stack list,
GitHub link, contact; Hostinger **Git deploy** configured (hPanel → Git → repository
`bryan-mcneil/forgotten-heroes`, branch `main`, directory `studio/site/dist` or a `studio-site`
orphan branch holding only the built files; webhook for auto-deploy); `studio/README.md` with the exact clicks.

**Sensei notes:** Hostinger deploys files from a Git branch into `public_html`; the simplest
reliable pattern is a GitHub Action that builds `studio/site` and pushes the output to a
`studio-site` branch, which Hostinger watches. Node apps are possible on Business plans but a
static page needs none of that.

**Verify:** your Hostinger domain (or temporary subdomain) shows the page over HTTPS; the Play button opens the dev game.

**Commit:** `step-59: studio landing page and hostinger deploy`

**Commit:** `step-60: icons, open graph and pwa manifest`
